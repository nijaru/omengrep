# og retrieval quality — 2026-09-03

Og-only numbers. Fixture + harness committed (`bench/qrels.json`,
`bench/eval.py`, `bench/fixtures/qrels-corpus/`); rerun any time.

## Setup

- Corpus: frozen omengrep source (new `crates/` + legacy `src/` as
  `old-src/`), 62 files / 418 blocks. Old and new og share `.og/`, so
  eval uses identical copies (`/tmp/qrels-new`, `/tmp/qrels-old`).
- 24 queries (12 identifier, 12 NL task-style), 38 binary relevance
  judgments written from code knowledge, mechanically validated to
  resolve to real blocks. Metrics: MRR, Recall@5/Recall@10.
- Configs: new hybrid (potion default), new BM25-only (`--no-semantic`),
  old og hybrid (LateOn-Code-edge, omendb) as reference.

## Continuity (parity) vs old og

Top-k block overlap on a 12-file fixture: IDENT top-5 0.49 / top-10
0.54, NL top-5 0.27 / top-10 0.45 (`bench/parity.py`). The BM25-only
ablation agrees with old og at the same rate as hybrid, so divergence
is the lexical layer (identifier splitting, FTS5 tokenization, BM25
defaults, RRF fusion) — not the vector channel overpowering. Exact
identifier definitions win in both engines (e.g. `parse_file_reference`
#1 at 5.7× #2). Verdict: moderate continuity, no engine breakage.

## Reading

- New hybrid beats old hybrid overall (MRR 0.678 vs 0.345), driven by
  identifier lookup (0.812 vs 0.246, R@10 1.000 both new configs).
- Vector channel earns its place on NL (MRR 0.417 → 0.544,
  R@5 0.319 → 0.500) at a small ident-MRR cost (0.917 → 0.812).
- NL is roughly at parity with old (MRR edge new, R@10 edge old).

## Caveats (no public claims)

Judgments by the implementer on their own codebase (bias possible),
n=24, binary relevance. The Semble-style task-level A/B (tool calls,
input tokens, agent time) is specified in `bench/agent-ab-protocol.md`
and remains required before any public quality claim.
