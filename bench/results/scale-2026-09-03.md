# og scale gates — 2026-09-03

Og-only numbers (project policy: public benchmarks report og alone).
Methodology: ripgrep-style — hyperfine, 3 warmup + 10 runs per query
(100 runs for p50/p99), 8-query mix of identifier + NL queries.
Corpus: `bench/gen_corpus.py` (seeded, deterministic), Rust, ~8 blocks/file.

Environment: Apple M3 Max, 16 cores, 64GB RAM.
Toolchain: rustc 1.93.0-nightly (83e49b75e 2025-12-03), release profile.
Model: minishlab/potion-code-16M-v2 (256-d static, HF cache, offline).
Raw logs: /tmp/raw-scale-fp16.txt, /tmp/p99-{10k,100k,500k}.json (rerun
`bench/scale.sh` to reproduce; ~10 min for all three scales).

Per-query means are flat across query types (80–89ms @10k, 140–170ms
@100k, 410–560ms @500k); distributions tight (σ < 5%). ~80ms floor is
process startup + model load + index open; `--no-semantic` answers in
~22ms total at 10k, so retrieval itself is single-digit ms at that scale.
Index density ≈ 1.4 KB/block (0.9 catalog incl. FTS+content, 0.5 vectors).

## Gate verdicts

- **Search RSS < 500 MB: PASS** at all scales (423 MB @500k). Flat exact
  scan stands — **no ANN/usearch needed**. (f32 sidecar measured 675 MB
  @500k and failed; fp16 port fixed it with cosine deviation < 1e-3.)
- **Bounded timeout: PASS.** 500k builds in 47s (~10.6k blocks/s);
  p99 575ms @500k.
- **Build RSS exceeds 500 MB transiently** (603 MB @500k, 47s window).
  Structural search-path gate passes; build-time RSS is a tuning knob
  (batch caps, sqlite cache_size), filed as follow-up, not a gate failure.

## Fixes driven by this gate (same task)

1. **fp16 sidecar** (`vectors.rs`, schema v1→v2): halves sidecar + scan
   RSS. Found + fixed during measurement: generation name omitted schema
   version, so a schema bump silently discarded the fresh build and kept
   the old row format behind for the new reader. Name now mixes
   content + model + schema.
2. **Offline model resolution** (`potion.rs`): every invocation paid
   ~2.4s of HF revalidation (query p50 was 2.5s). Cache lookup
   (`Repo::get`) first, download only on true miss. Query p50
   2.5s → 84ms @10k.
